# 检索（FTS）实现与边界

> 状态：当前实现是 bigram 预分词；**可选分词插件待定**（商协会交付完成后再定）。
> 本文记录的是实测结论，不是设计愿望 —— 目的是让以后重新评估时不必再调研一遍。

## 当前实现

- SQLite FTS5 表 `nodes_fts`，contentless（`content=''` + `contentless_delete=1`），写路径同事务同步。
- 中文按 **bigram** 预分词（`core/search.go` 的 `bigram()`）：CJK 段 2 字滑窗，非 CJK 段保留原词。
- 三个列与 bm25 权重：`type` 0、`display` 10、`body_text` 1。
- 查询侧把每个词元包成 FTS5 短语。**FTS5 的查询语言和 SQL 参数绑定是两层**：`#{n}` 只保护 SQL 那层，
  MATCH 后面的字符串还会被 FTS5 再解析一次，`ftsPhrase` 负责按 FTS5 规则转义（内部 `"` 翻倍）。
- 索引重建：迁移之后跑一次；换检索实现**不会**自动触发。

## 查询语义（三级放宽）

1. **精确子串** —— 整个查询作为一个 phrase（连续 bigram = 原文子串）。
2. **丢语料里不存在的 bigram 后 AND** —— `农业著名` → 农业 AND 著名。
3. **OR 兜底** —— 宁可多给，不要空手。

第 2 级只丢"语料里查无此词"的 bigram：跨词边界的接缝（`业著`）本就该丢。
第 3 级用于接缝恰好存在时（`企业著称`），此时靠 bm25 排序，**不保证覆盖度优先**。

## 实测边界

每条都在真实库或测试里验证过（`core/search_test.go`）。

| 现象 | 实测 | 原因 |
|---|---|---|
| 单字查询搜不到 | `农` → 0 条 | 索引里只有 bigram；单字仅在该段恰为单字时写入 |
| 多词查询需放宽才命中 | `农业著名` → 1 条（放宽后） | 接缝 bigram 让整条 phrase 归零 |
| 接缝串假命中 | `业著` → 命中 `企业著名` | 接缝在索引里真实存在 |
| 覆盖度不保证排序 | OR 级 4 条里混着只含一个词的 | bm25 以 bigram 为单位，且有长度归一化 |
| 假名/韩文不可用 | `がな` → 0 条（整段一个词元） | `cjk` 范围写死 U+4E00–U+9FFF |
| 简繁不互通 | `农业` ≠ `農業` | 索引存码点，无映射 |
| 拉丁/数字正常 | `AI`、`ai` 均命中 | 非 CJK 段保留原词 + unicode61 折叠大小写 |

用户输入不会变成 FTS5 语法（`AND`、`a:b`、`abc*` 都只是普通词），见
`TestSearchTreatsFTSOperatorsAsTerms`。

索引代价：每个汉字最多进 2 个 bigram（词元数 ≈ 2× 字数）；1M 节点 6.8KB/节点（contentless 前 15.5KB）；
常见词检索按命中集线性增长（1M 基准 44.8s）。

## 可选分词插件（待定，不阻塞当前交付）

**动机**：上表里"单字搜不到 / 多词需放宽 / 接缝假命中 / 排序"几条都来自同一件事 —— 不知道词边界。
分词还能给出 bigram 给不了的能力：**用户词典**（`商协会`、`专精特新`、`光伏产业` 这类行业词，
bigram 只能切成 `专精`/`特新`）。

**落点**：实现 `core.SearchIndex`（`SetSearchIndex` 注入），内核**保持零依赖**，启用是调用方的一行代码。

**选型**（实测 + 许可证）：

| 库 | 许可证 | 词典 | 加载 | 热吞吐 | 词典常驻 |
|---|---|---|---|---|---|
| **lengzhao/jiebago**（选它） | MIT | 模块内置 4.8MB | 621ms（懒加载） | 2.71 MB/s | 35MB |
| fumiama/jieba | **AGPL-3.0 ✗ 出局** | 外置 4.8MB | 123ms | 4.63 MB/s | 31MB |
| go-ego/gse | Apache-2.0 | 多套，模块 55MB | — | — | — |
| vogo/sego | Apache-2.0 | 8.2MB | — | — | — |

最快的那个是 AGPL，商用站点不能用 —— 先看许可证再看性能。

**体积代价**（实测，站点二进制）：

| 情况 | 增量 |
|---|---|
| 包在模块里但没人 import | **+0**（`go list -deps` 里依赖出现 0 次） |
| blank import，无可达引用 | +0.41MB（符号级裁剪：词典未被引用即丢弃） |
| 可达引用（含 `init` 自注册） | **+5.37MB**（30.19 → 35.56MB） |

所以 wiring 必须守三条：内核不 import 任何插件、每个 `main` 只 import 自己需要的、插件不在 `init` 里
引用重数据（自注册形态会让所有链接它的站点都背上词典）。

**换实现的开销**：必须重建一次全文索引。1M 节点按 1–2 小时估（bigram 现状 13m37s）。
只影响 FTS —— 每次启动重建的 `gcm_schema_*` 实测 1M 节点约 2s，与分词无关。
